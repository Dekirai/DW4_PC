# Roadmap and acceptance criteria

The selected implementation is a complete native source port: reconstruct the
original game and engine behavior in authored C++20 (`dw4_core`, `dw4_engine`,
`dw4_game`). The earlier DolRecomp/ModernGekko experiment was removed from the
source tree and does not establish features in the native engine.
A successful build, decoded record or settings control alone does not establish
playable behavior. The full original game, PC features, modding, online co-op and
simple ROM-driven release experience remain required. Gate 1, the 1:1 port of the
original game, is the reference: the game is playable from a new game to the
cleared game (also without cheats, local 1-4 players, lockstep online co-op).
Since 29 October 2026 the focus is everything a player notices, under one rule:
whenever a new feature is off, the original behaviour stays exactly as it is
(the determinism reference, save states, the automated story runs and the
Dolphin comparisons depend on it). The current plan is the online / PC feature
package in gates 3-5: seamless online co-op on the project's own server with
accounts, a website, achievements and cloud saves, a plain save file with
GameCube save import, an enemy and loading zone randomizer and Discord Rich
Presence. Its first phase (round 48) is joined: the save file and import, name
tags, Discord Rich Presence, local achievements, the randomizer and the
complete server side; the game client of the seamless co-op is next. PS2 save
import is deferred (no samples).

| 6 | Simple EXE release | User selects their ROM; supported revision is validated and required assets prepared automatically, without a compiler or manual extraction; repeat launches reuse validated local data; portable saves beside one EXE entry point | The runtime reads the game straight from an uncompressed GDJEB2 disc image or a Dolphin extraction; the first start asks for one (file or folder dialog), checks the game id and revision and saves the path in settings.ini. Saves default to saves/savedata.dat next to the program (an older saves/GC/USA save is copied there once); the EXE links the C++ runtime statically (only system DLLs), so no redistributable is needed. RVZ images are converted once into a plain image next to the program (a GameCube RVZ converted this way matches its Redump SHA-1). `cmake --install` (or `scripts\build.ps1 -Package`) lays out the release around a single DW4_PC.exe; copied to a fresh folder it runs from the disc image with no other files. A test on a fresh Windows installation remains. |

Gate order sets the immediate queue, not an excuse to design out later features.
The final native application must provide one `DW4_PC.exe` entry point with
user-provided assets and portable save data beside it. The in-game ImGui menu
must open with **F1**, receive the current File/View commands and apply supported
settings while playing. These remain native integration requirements.
Preserve every existing save and use explicit migration where formats differ.

Keep rendering enhancements separate from simulation speed; a speed multiplier,
duplicated presents or an FPS slider alone cannot satisfy the 300 FPS target.
Higher internal render resolution and higher-resolution texture content also
have separate acceptance checks. Report hardware, scene, settings and measured
frame times with each performance claim; 300 FPS is a target, not a guarantee
for every device or scene.

## Requested extensions

- **HD texture packs:** done: dumps and replacements by pixel hash (`mods/textures`).
- **Mod loader:** done: `mods/<id>/mod.ini` (version, priority, target disc), files by logical path, F1 toggles.
- **Custom maps:** replaced stage packages load through the mod loader; import tools remain.
- **Custom Digimon:** actor definitions, meshes, rigging, animations and abilities.
- **Custom weapons:** weapon data, models, animation hooks and damage behavior.
- **Randomizer:** item drops, enemies and dungeon entrances done (one seed bound to the save, spoiler log); the coupled shuffle of all two-way loading zones remains.
- **Difficulty rebalancing:** EXP rate and damage dealt / taken options done.
- **Bug fixes:** reproductions and regression checks against recovered behavior.
- **Online four-player co-op:** lockstep sessions done; seamless co-op through the project's server is the current plan (server side done, game client next).

Keep each increment buildable and publish source progress to this repository.
Do not distribute the user's ISO, DOL, extracted assets or generated asset packs.
