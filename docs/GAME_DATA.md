# Native generated game data and model HP binding

`GameDataState` implements the complete common and four-player named-data
graph generated by the original GAMERAM initialization. `bind_model_game_data`
implements the later, separate post-GETPLAYER HP/MHP binding and conditional
HP/MP refill prefix. These components preserve shared object identity. They
do not perform save loading, player selection, stat/equipment calculation or
the remainder of player construction. Factory HP is zero; it is not an
invented starting HP for a ready player.

## Original provenance

The reference is the supplied USA `sys/main.dol`, SHA-1
`e409a88a7379ed1a536f93b0a303a0ce7cd5d877`.

- `8036D224` creates the common list at manager `+40` and player-list-list at
  `+44`, then invokes `8036CE1C` for indices 0, 1, 2 and 3.
- `8036C2B0` consumes 12-byte schema records: signed kind, list count and name
  pointer. The common schema at `804EA930` has 13 records; the player schema
  at `804EA9D8` has 64. Both terminate with kind `-1`.
- `8036CE1C` fills the schemas and applies the additional player defaults
  described below. It replaces the selected player row.
- `8034D990..8034DA74` consumes the retained GETPLAYER row, binds HP/MHP and
  applies the exact-zero HP branch. The preceding messenger request and the
  rest of the player constructor remain separate operations.

## Exact generated values

All scalar integers and boolean bytes start at zero. Numeric lists contain
zero values; FloatList values are positive zero words. String payloads and
StringList elements are null, distinct from non-null empty strings. ObjectList
elements are null slots. Every list wrapper owns a non-null list object, even
when its count is zero.

The scalar defaults follow the original field metadata and zero-default
initializer. The list constructor explicitly fills IntList from `804EACE4`,
BoolList from `80561410` and FloatList from `804EACE8`; these are zero. String
and object slots are explicitly filled with null references. String interning
at `80054094` preserves a null input as null.

`8036CE1C` then makes exactly these additional player-data changes:

- All 16 `BASE_LEVEL` integers become 1 (`8036CFFC..8036D040`).
- All 144 `BASE_SKILL` integers become 1 (`8036D060..8036D0B8`). The nine
  ordinary `SKILL` values remain zero.
- `DISKFOLDER` receives 12 distinct `beNDMWItemDisk` objects
  (`8036D0BC..8036D144`). Each has kind number 4, record number equal to its
  slot 0 through 11, equipment byte 0 and count 0.
- `BASE_FLAG[960]` becomes byte 1 (`8036D16C..8036D174`). All other base flags
  and all common `FLAG` values remain zero.

Disk initialization is explicit in `803B10A0`: kind number at `+08`, signed
record at `+0C`, equipment byte at `+10`, signed count at `+14`.
`beNDMWItemDisk` is size `0x18` and inherits `beNDMWItemBase`, size `0x14`,
whose base is `igObject`. `GameDataDisk` therefore has no invented name.
Padding is not exposed as a logical default. Other inventory and equipment
lists keep their authored empty or null-slot state.

## Shared ownership, lookup and reset

`GameDataList` holds ordered shared wrappers. Array wrappers additionally hold
shared list owners, so retrieving either a wrapper or its list preserves live
aliasing. `ModelScriptInt` is an alias of `GameDataInt`; model work and a
GAMERAM row can refer to the same HP object without conversion or value copying.

`find<T>(name)` and `require<T>(name)` compare exact name bytes. They skip null
names, distinguish empty names, and stop at the first name match. A wrong
type at that first match throws instead of silently finding a later duplicate.
This follows named lookup `8031F3CC -> 800695CC`, whose comparison is `strcmp`
at `8006962C`. Ordered duplicate references remain present.

`GameDataState` owns one stable common list and four independent player rows:

- `common()` returns the existing shared common-list owner.
- `player(index)` returns the existing shared row for index 0 through 3.
- `reset_player(index)` replaces only that player row. Resetting index zero
  also repopulates the **same common-list object** with fresh fields.

Retained old rows, wrappers, arrays and disk objects remain alive across reset.
Existing model work continues referring to its old HP/MHP objects until an
explicit later preparation rebinds them. An unretained obsolete object is
released normally. The generated state cannot be copied or moved into an
accidental second owner. Native manager/info/RAM identities and messenger
registration belong to the separate GAMERAM runtime.

## Captured GETPLAYER HP prefix

The caller supplies the actual retained row returned by its completed
GETPLAYER delivery:

```cpp
auto binding = bind_model_game_data(work, captured_getplayer_row);
```

The helper implements this represented order:

1. Look up first named `HP` and publish that shared object in work HP
   (`8034D9D8`).
2. Look up first named `MHP` and publish that shared object in work maximum HP
   (`8034DA24`).
3. If the new HP value is exactly zero, read current MHP and copy it to HP
   (`8034DA44..8034DA54`). Then read current MMP and copy it to MP
   (`8034DA64..8034DA74`).

Negative HP skips both copies. Zero or negative maxima are copied exactly;
there is no clamp or positive fallback. Skipping the branch does not require
MP/MMP fields. Record, matrix and other work fields are unaffected by this
prefix. The result retains `row()`, `hp()` and `max_hp()`; `refilled()` reports
whether the zero-HP branch ran, including when the resulting values remain zero.

A nested call or later recipient may reset the manager after GETPLAYER has
already appended its result. The original consumes that captured old object.
The helper therefore does not re-fetch a current row or require equality with
the manager's replacement row. The caller remains responsible for the actual
GETPLAYER delivery and for choosing its captured result.

## Checked host boundaries and validation

The synthetic named-row constructor rejects absent typed wrappers/list owners,
nonfinite float values, embedded NUL strings, excessive nesting and bounded
allocation excess: 4,096 named entries, 65,536 traversed objects/list elements,
32 nested object-list levels, 4,096 bytes per string and 1 MiB aggregate text.
Null object slots and nullable strings remain valid. Later live payload edits
are owned by their callers; this component is not a general save/IGB restorer.

Construction/reset completes checked allocation before publishing changes.
Malformed binding rows are prevalidated before any HP reference or refill
mutation. These are explicit host failure boundaries: original initialization
publishes intermediate changes earlier and does not provide these checked
failure guarantees. Successful represented effects preserve the original order.

The isolated `/W4` builds pass without warnings. `dw4_game_data_tests` has
8,178 synthetic checks covering every generated field and array element,
all four independent rows, 48 initialized disks, names/types, aliases, resets
and malformed profiles. Its optional original-data run has 8,266 checks,
comparing all 77 schema records and both sentinels directly with DOL bytes,
plus exact initialization constants and disk setter instructions:

```text
dw4_game_data_tests [EXTRACTED_ROOT]
```

`dw4_model_game_data_tests` has 59 checks covering all four work owners,
signed and exact-zero branches, captured rows after reset, first-name type
rejection without partial effects, and actual `ModelScriptContextRuntime`
publication/HP epilogue sharing. These are schema/default, ownership and
represented-prefix checks; they do not execute the entire original factory
or establish complete player preparation.
