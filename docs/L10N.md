# Display languages (fan translations)

The USA disc has English only ([LOCALIZATION.md](LOCALIZATION.md)). The port can
show the game's text in another language as a **presentation layer** over that
English text: a language pack next to the program maps each English text to its
translation, and the text lines are laid out with the translation instead. The
first pack is a German fan translation ("Deutsch (Fan-Übersetzung)").

Phase 1 (this document) is the engine, host and tool side. The German catalog
itself (`game.tsv`) is derived from the game's script; it is made and kept on the
translator's machine and never committed or shipped.

## 1. What never changes

* The English text of the USA disc stays the source and the key. `usa_pack.igb`
  is always loaded; `SYSgetCountry` / `SYSgetArea` keep returning USA. Loading
  another region's pack instead changes the stage load timing (measured:
  `ger_pack.igb` in place of `usa_pack.igb` moves dng101b1's load by 30 frames
  and the det fingerprint to 5b8323ca), so the port never does that.
* Lua, the database, messenger packets, `TextCtlManager::Line::text`,
  `PanelRam::line_text`, the tick state, saves, save states, snapshots, input
  logs and everything an online session sends keep the English text. The
  language is in no fingerprint, `data_hash`, `settings_hash`, save or protocol
  message: players with different languages play the same session, each seeing
  their own language (a joiner lays the English text it receives out again in
  its own language).
* A language pack is not a content mod (`mods/` would change the data hash).
* Database key columns (LABEL, ZOKUSEI, KOUKA, SHUSEINOURYOKU, MODEL,
  MODEL_NAME, NAME's emptiness) are never touched: they only ever exist in
  English.
* Data Overflow (paused) keeps its own English texts and font loader.

Measured with the det path (work/dref/checks/det.sh's 6000-frame new game into
dng101b1, two runs each): English, German with a full test catalog, German with
half a catalog, and a switch between English and German every 500 frames all
give fingerprint 4004f056 and audio 396cb219; the save state suite stays 17/17.

## 2. Language packs

A language pack is a folder `lang/<code>/` next to the program. F1 lists English
plus every folder with a usable `language.ini` (at most 64 KB; folder and file
names may be any UTF-8, they are used as UTF-8 paths). A folder that cannot be
used (no or a broken `language.ini`, a name the file system cannot give back)
is skipped and logged on its own; it never stops the others or the program. The build copies
`data/lang/<code>/` (committed) and a translator's `local/lang/<code>/game.tsv`
(git-ignored) there (`cmake/copy_lang.cmake`); nothing of it is installed into
release packages yet.

| File | Content | Committed |
| --- | --- | --- |
| `language.ini` | `[language]` code, name (in its own language), revision (the English corpus SHA-256 the catalog was made for), token_format; `[files]` game, textures, ui (reserved for the port's own UI) | yes |
| `game.tsv` | the game text catalog (below) | **no**: derived from the game |
| `textures.tsv` | picture swaps by the USA texture's hash | yes (hashes only) |

### game.tsv

UTF-8, one entry per line, `#` lines are comments (`# revision=<sha>` names the
corpus), an optional header row whose first column reads `id`:

    id <TAB> english <TAB> translation [<TAB> flags [<TAB> notes ...]]

* **id**: empty (or `*`) for a content entry, which applies wherever that
  English text is shown. `<stage>/<mswkName>` overrides one pack string where
  the same English sentence needs another translation; it applies only while
  the line shows exactly that pack string (a TEXTSET by index), else the content
  entry does. A line rebuilt from the tick state (a loaded save state, a seamless
  co-op join, `Engine::rerun`) has no pack index until its next TEXTSET and shows
  the content entry, so an id row always comes with a content row for the same
  English text (the lint warns about one without). `db:<table>:<row>:<column>`
  records a database cell's origin and applies as a content entry (the engine
  does not know which cell a text came from: one English text has one
  translation in every table, e.g. "Speed" in the status window and in the
  dungeon panel's status effect list).
* **english / translation**: the token form (format 1):

  | Token | Code point | Meaning |
  | --- | --- | --- |
  | `{BR}` | CR LF | line break (`{CR}`, `{LF}`, `{TAB}` for lone ones) |
  | `{A}` `{B}` `{B2}` `{X}` `{Y}` `{START}` `{L}` `{R}` `{Z}` `{DPAD}` `{STICK}` `{CSTICK}` | U+226A U+226B U+2220 U+2252 U+2312 U+22A5 U+221A U+4E9C U+2235 U+2261 U+2207 U+5A03 | controller button glyphs (the prompts draw each player's own) |
  | `{I_WEAPON}` `{I_ARMOR1}` `{I_ARMOR2}` `{I_CHIP}` `{I_DATA}` `{I_FIRE}` `{I_ICE}` `{I_THUNDER}` `{I_DARK}` `{I_EQUIPPED}` | U+2208 U+220B U+2228 U+2227 U+00B6 U+2282 U+2283 U+222A U+2229 U+2286 | item icons |
  | `/` `;` | U+3042 U+3044 | the US font draws its slash and semicolon in these cells (it has no ASCII `/` or `;`) |

  Everything else is literal text.
* **flags**: comma separated. `squeeze=0.90`..`0.99` scales the laid-out lines
  horizontally (the last resort for a text that does not fit after
  shortening; the lint says when one is needed); `fuzzy` keeps the English text.

A broken entry (bad UTF-8, an unknown token, other button / icon tokens or
another order than the English text, a lost word START, a squeeze below 0.90,
a second different translation of the same English text) is rejected on its
own: that text stays English. A translation the font cannot draw is shown in
English too (and logged by `DW4_L10N_MISSES`).

### textures.tsv

    <usa hash> <TAB> <image name> <TAB> <source>

The hash is `TexturePack::hash` (16 hex digits) of the USA texture. Sources:
`disc:<pack>:<hash>` is the same image from the player's own disc (found by name
in `<stage>/separate/<pack>.igb`, dng101b1 first, at most 16 packs, checked by
its hash), read by the host outside the engine's load queue;
`render:<recipe>` is drawn at run time with the game font from the catalog.
The German pack swaps three pictures:

| USA texture | German picture |
| --- | --- |
| stmojipnl01.png dce3cec48abddbd1 (Strength / Defense / Wisdom / Spirit / Speed ...) | ger_pack original a54ea4388dccd54a (Stärke / Verteidg / Weish. / Geist / Geschw ...) |
| bit.png 8328a86358ddcecb (BITS) | ger_pack original 8891780d65461abd (BIT) |
| stcngmoji.png 82504a8ec6521575 (travel dialog) | `render:travel_dialog`: the catalog's translations of "Go to the destination." and "Stay here." drawn with font00's glyphs, a black outline and a shadow, centred in the original's two 32-row bands (none: the English picture stays) |

Every other picture with English text (title menu, logo, loading cards, cards,
credits, "Lv. HP MP") stays as it is, as the PAL packs left them too.

## 3. Engine (presentation only)

* `TextCtlManager::set_text` stores the English text as before and lays out its
  display form (`layout_line`). Without a catalog the original path runs bit for
  bit.
* The display form: a TEXTSET by index remembers the pack string's index
  (`Line::pack_index`, not in the tick state) for the `<stage>/<mswkName>`
  override; otherwise the content entry; then the compound rules for C++-built
  texts: a leading equip marker (U+2286 / U+8D6B) before a database NAME and one
  trailing rank digit after a database TXT are kept around the translated core
  (subwnd_shop.cpp, subwnd.cpp). Anything unknown (numbers, names, name entry
  characters) passes unchanged.
* `DW4_L10N_MISSES=<file>` appends every shown English text with letters that
  has no usable translation, once per run (`id <TAB> layer/line <TAB> missing|glyph
  <TAB> text`): new C++ compositions and catalog gaps show up there. In the
  German campaign review only two kinds came up: the Digi-Lab list's "Lv"
  (subwnd_shop.cpp / subwnd_skill.cpp; the catalog has a row for it) and the
  MP / item menu's counts "x4".."x9" (WZXFONT; a number, the same in German).
  `DW4_TRACE_TEXT` logs the English text as before plus a `text shown` line for
  the displayed one.
* `Engine::set_display_text(catalog)` (between two steps) lays every line that
  shows a text out again from its English source: originals, seamless co-op
  copies and hidden lines (a later `SWITCH SET` shows the language at once). A
  line INITIALIZE emptied stays empty; a relayout keeps the alignment the text was
  laid out with and replaces the line's geometry instead of adding one. The
  renderer's and the prompts' caches follow the new geometry by its serial.
* Fonts: translations are laid out with display fonts (`make_display_font`): the
  game fonts' metrics plus „ “ ‘ composed from ” and ’ (the cells at 258/260,
  274/260 and 290/260 in 512ths, in font00's empty area x ≥ 256, v ≥ 256), the
  aliases ‚ (comma) – (hyphen, 14 px wide) — (ー), and Ä Ö Ü ä ö ü ß raised by one
  texel (their cells stand one texel lower). The original fonts stay untouched,
  so English lays out exactly as before. The renderer paints the composed cells
  into the font atlas when it uploads (`GlRenderer::set_font_atlas`), in
  normalized coordinates, so a texture pack's larger font00 gets them at its own
  resolution.

## 4. Host

* `settings.ini` `[preferences] language = en | <code>`; F1 > Settings >
  **Language** lists the languages in their own names ("English",
  "Deutsch (Fan-Übersetzung)"; "(pictures only, no game.tsv)" for a pack without
  its catalog). A choice applies at once: the pack's files are read again (a
  translator sees an edited game.tsv by switching), and the engine takes the
  catalog before the next step. The port's own menus stay English for now
  (`[files] ui` is reserved for their catalog).
* The renderer takes the language's pictures by USA hash; a texture pack's
  replacement of a language picture is looked up by that picture's own hash (a
  4x pack can carry the German originals). Uploads hash their pixels only while
  a language with pictures is selected (or a texture pack is active): English
  costs nothing even with packs in `lang/`. A change uploads only the textures
  the old or the new set swaps (the first set with pictures: every texture
  uploaded without its hash, once).
* Test runs (`--smoke-test`) show English unless `DW4_LANGUAGE=<code>`; they
  may read the packs from `DW4_LANG_DIR=<folder>`, switch at frames
  (`DW4_L10N_SWITCH=F:code,F:code`, applied before that frame's step), switch
  every N frames between English and DW4_LANGUAGE (`DW4_L10N_SWITCH_EVERY=N`)
  and write the language pictures as PNG files (`DW4_L10N_DUMP=<folder>`).

## 5. Tools (tools/l10n)

    dw4_l10n export --research work/l10n_research/text --data <extracted disc> --out work/l10n/source/game_en.tsv
    dw4_l10n lint --source work/l10n/source/game_en.tsv --catalog local/lang/de/game.tsv --data <extracted disc> [--all] [--report FILE]
    dw4_l10n wrap --source work/l10n/source/game_en.tsv --catalog local/lang/de/game.tsv --data <extracted disc> --out FILE
    dw4_l10n measure --data <extracted disc> --file FILE [--font NORMAL|MINIMUM]
    dw4_l10n revision --source work/l10n/source/game_en.tsv
    python tools/l10n/pseudo_catalog.py --source work/l10n/source/game_en.tsv --out work/l10n_test/lang/de/game.tsv [--add exact.tsv] [--every N]
    python tools/l10n/merge_catalog.py --catalog local/lang/de/game.tsv --fragment work/l10n/chunks/P1.tsv [--fragment ...] [--resolve FILE] [--prefer catalog|fragment] [--source work/l10n/source/game_en.tsv] [--report FILE] [--strict]
    python tools/l10n/freeze_names.py --source work/l10n/source/game_en.tsv --catalog local/lang/de/game.tsv [--extra FILE] --out work/l10n/frozen_names.tsv

* **export** reads the text inventory (pack strings with the lines Lua sets them
  on, the database display columns, the card names; the dev stage stag0000 and
  texts without a letter left out) and writes one row per unique English text
  (4,512 for the USA disc). The file is a valid game.tsv with empty
  translations; its notes columns give the strictest **box** the text is shown in:
  `class`, `where` (first id), `boxes`, `font` (NORMAL or MINIMUM, which is NORMAL
  x 0.66), `max_width` (font units: the widest English line ever shown in that
  box, measured with the engine's layout; the data's field width is no hard
  limit, English exceeds it), `max_lines`, `align` (L / R / C), `field_width`,
  `copies`. Database texts are measured in MINIMUM per table and column; an
  Item's NAME and TXT get the field of the windows that show them (the lists'
  STWINFONT14, 1.68, and the description box STWINFONT29/font000, 3.52), an MP
  technique's TXT the same description box (its NAME also stands in the dungeon
  panel's list: no field). `max_lines` counts the lines that show something (a
  trailing `{BR}` adds none: the technique box shows 3). A box's
  **budget** is `max_width`, or `field_width` where that is wider (a short
  English word in a wide label: the status window's "Spirit" is 0.39 wide in a
  0.84 field); the strictest box is the one with the smallest budget. A field
  that reaches under its frame's decoration is no budget; the frame's opening
  is (`framed_width`): the enemy info card's description (DMINFOFONT02
  font02) has a 2.56 field whose right part lies under the card's yellow
  bars, so its budget is the 2.0 left of them (460 pixels at 1080 lines; the
  export writes no field for it, the lint ignores it in an older export too).
  Found in the German in-game review.
* **lint** parses the catalog with the engine's own parser and measures every
  translation with `layout_text` and the display fonts: tokens, glyphs, each
  line's width against the budget, the line count against `max_lines` (a memory
  card text keeps the English text's line count: the next line of its box is
  often the other half of the sentence, CHRSELFONT06 font000 / font001, or the
  options), the squeeze. Verdicts: OK, SQUEEZED (fits with its flag), NEEDS_SQUEEZE (fits only
  with a squeeze of at least 0.90 it lacks: an error), ERROR (rejected by the
  engine, a missing glyph, too wide, too many lines), WARNING (numbers differ, a
  `:` ending lost, other leading / trailing `{BR}`s than the English text, an id
  row without a content row, not in the corpus). Rows that do not fit get a
  greedy rewrap suggestion when one fits. Its edges (leading and trailing
  spaces and `{BR}`s) stay as they are; the translation's own line breaks are
  kept first (a line that fits stays as it is, a longer one is wrapped on its
  own); when that gives too many lines, a text is wrapped as one paragraph,
  except database texts: an MP technique or Digivolution text keeps its heading
  line ("MP 8 Heal Skill Up") and wraps the rest, an equipment or chip text
  (requirement / text / "Mods:", value / slots / data) keeps every line and gets
  no suggestion. A number or an Item / element icon stays on the line of the
  word after it ("1 Punkt", "{I_ARMOR1} Rüstungs-Board"). Exit code 1 on errors.
* **wrap** writes the catalog with those suggestions put into the translation
  column (every other line as it was): translators write running text with
  `{BR}` only where the structure needs a line of its own (options, a heading
  line, a database text's last line) and let the tool break the rest; the lint
  afterwards shows what still does not fit.
* **measure** prints each line's width of every text in a file (one text in the
  token form per line): for trying wordings against a box's budget.
* **pseudo_catalog.py** writes a pseudo translation (umlauts, ß, „ “ ‚ ‘, tokens
  kept) to test the whole path without a real translation.
* **merge_catalog.py** merges translation fragments (game.tsv form, one per
  translator package) into the catalog by key (id, English text): new rows are
  appended in fragment order, identical rows skipped, so merging again changes
  nothing. A key with two different translations (or flags) is a conflict: the
  catalog's row stays (or the fragment's, `--prefer fragment`) unless a row of
  the `--resolve` file decides it; the report also lists English texts that
  differ only in edges or case but got different translations, and fragment rows
  not in the export. `--strict` exits 2 on an unresolved conflict.
* **freeze_names.py** lists every database and card name with its catalog
  translation (plus `--extra` rows such as speakers or status labels), each
  also in its bare form without icons, the way dialogue quotes it: the names a
  dialogue translation has to use exactly. It reports names still without a
  translation and bare names with two translations.

Rules for translators: keep every button and icon token in its order, keep the
word START (the prompt draws it as a picture; "START-Taste" works), write `/`
and `;` normally, use „ “ ‚ ‘ – — ä ö ü ß freely (the font's own … is a small
centred Japanese ellipsis: write "..." instead), and none of
`% € « » # $ * = @ [ ] \ ` { } ~` (the font lacks them). One dialogue page stays
one page (Lua counts pages). A database TXT that ends in `:` gets a value
appended by the game and keeps its `:`. A text keeps the English text's
leading and trailing `{BR}`s (they place it in its box; `wrap` keeps them).

## 6. For the 4x remaster textures

* The German originals a54ea4388dccd54a and 8891780d65461abd need 4x versions
  of their own (they are not USA textures); a pack replaces them by these hashes.
* A 4x font00 must keep the same normalized layout and leave x ≥ 256, v ≥ 256
  empty: the composed glyph cells are painted there at the pack's resolution.
